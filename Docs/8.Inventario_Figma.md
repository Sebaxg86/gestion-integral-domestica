## 1. Propósito

Este documento registra el estado implementado del archivo de Figma después de
adaptar la [Guía de diseño UI del MVP 0](7.Guia_diseno_UI_MVP_0.md). La guía
continúa siendo la fuente de criterios; este inventario indica qué existe
actualmente en Figma y dónde consultarlo.

La paleta azul brillante inicial se trató como una exploración descartada. El
sistema usa una dirección neutral first: blanco y gris frío casi blanco para
estructura y volumen, azul acero para acciones principales y color semántico
únicamente en indicadores pequeños o feedback transitorio.

Los componentes consumen roles semánticos como
`color/action/primary/default`, `color/text/primary`,
`color/status/danger/background` y `color/border/focus-on-strong`; no dependen
directamente de la paleta primitiva.

`color/surface/elevated` representa las tarjetas blancas sobre el fondo gris. Los
fondos success, warning, danger e info utilizan primitivas alpha al 6 %; sus
bordes semánticos resuelven a un mismo gris neutro.

### 4.3 Validación de variables

La auditoría final obtuvo:

- Cero variables sin valor en su modo.
- Cero variables con scope `ALL_SCOPES`.
- Cero variables sin sintaxis `WEB`.
- Todos los tokens de color migrados al modo claro y vinculados a primitivas.

## 7. Patrones de composición

La página `03 — Patterns` contiene tres patrones aprobados:

1. `Mobile app shell`: app bar de 64 px, contenido con margen de 16 px y
   navegación inferior de 80 px.
2. `Form wizard`: progreso explícito, campos centrados, ayuda contextual y una
   acción primaria al final.
3. `Prioritized content`: resumen numérico y listas ordenadas por urgencia, sin
   depender únicamente del color.

La misma página recuerda las reglas transversales de área táctil, foco visible,
confirmación de acciones peligrosas y navegación por breakpoint.

## 10. Convenciones de mantenimiento

- Mantener `90 — Archive` para elementos retirados que conviene conservar.
- Mantener `99 — Playground` para experimentar y jugar sin comprometer el
  sistema aprobado.
- Crear una variable semántica antes de introducir un color repetido nuevo.
- Extender un component set antes de duplicar un componente con otro nombre.
- Validar contraste, foco, touch target y estados alternos antes de promover una
  exploración al sistema.
- Actualizar este inventario cuando cambien páginas, tokens, componentes o
  pantallas aprobadas.
